二、消息编辑

编辑工作流

  1. 先用 await view_msg(id) 获知当前内容和行号
  2. 选用下方编辑函数
  3. 所有编辑函数均支持 id 为 str（单条）、list[str]（多条）或 'all'（全 dialog）
  4. update_output=True 可编辑输出而非 content
  5. 返回值：单 id → diff 字符串；多 id → [(id, diff), ...]

字符串替换

await msg_str_replace(id, old_str, new_str, start_line=None, end_line=None,
    n_matches=None, re_filter=None, invert_filter=False, *,
    update_output=False, dname='', log_changed=False)

精确替换 old_str → new_str。n_matches 限制次数；re_filter 只作用于匹配该正则的行。

await msg_strs_replace(id, old_strs: list[str], new_strs: list[str], ...)

同时替换多对字符串，一次调用完成。

行级编辑

await msg_replace_lines(id, start_line, end_line=None, new_content='', ...)
await msg_del_lines(id, start_line, end_line=None, re_filter=None, invert_filter=False, ...)
await msg_insert_line(id, insert_line, new_str, ...)

Exhash（hash 验证行编辑器）

await msg_lnhashview(id, dname='') -> str

获取 lineno|hash|content 格式的带地址行。

await msg_exhash(id, cmds: list, dname='') -> str

按 hash 地址执行 ex 风格命令，hash 在每条命令执行前校验。

地址格式： 12|a3f2|cmd（单行）或 12|a3f2|,15|b1c3|cmd（范围），0|0000| 只能配合 a/i。

命令： - s/pat/rep/[flags] — 替换（g=全局, i=忽略大小写） - d — 删除 - a / i / c — 追加 / 插入 / 替换（文本紧跟命令后换行，无需 . 结束符） - j — 合并行 - m dest / t dest — 移动 / 复制到目标地址后 - >[n] / <[n] — 缩进 / 反缩进（默认 4 空格） - sort — 排序 - p — 打印（不修改） - g/pat/cmd / g!/pat/cmd — 全局匹配行执行命令

关键规则： 多条命令从后往前执行（防行号偏移），必须使用 msg_lnhashview 获取地址后立刻编辑。

Python 编辑

await msg_python(id, code, ...)

用 Python 代码编辑消息内容，text 变量保存当前 content，最后一个表达式为新 content。

nbdev Concise Reference

版本: nbdev 3.x (2026年1月起) | 配置: pyproject.toml（[tool.nbdev]）| 从 nbdev2 迁移: nbdev-migrate-config

概述

nbdev 是一个 笔记本驱动的开发平台。在 Jupyter Notebook 中编写代码、测试和文档，自动获得：

  • Quarto 文档：自动生成，支持 LaTeX、搜索、超链接（含跨包 doclinks，通过 nbdev-index）
  • Python 打包：发布到 PyPI 和 conda，自动管理 __all__
  • 双向同步：notebook ↔︎ .py 模块，每个导出 cell 带有唯一 cell ID
  • 并行测试：nbdev-test 并行运行所有 notebook 中的测试 cell
  • CI 开箱即用：GitHub Actions 自动测试和部署文档
  • Git 友好：自动清理元数据、人类可读的合并冲突

安装

pip install nbdev
# 还需要 Quarto:
nbdev-install-quarto

仅支持 macOS / Linux / WSL。必须与 Jupyter 在同一 Python 环境。

指令（Directives）

指令是 #| 开头的特殊注释，控制 cell 的可见性、导出行为和执行。

可见性

指令 效果
#\| hide (📓) 隐藏整个 cell（输入+输出）。等同 Quarto 的 #\| include: false
#\| echo: false (🔵) 隐藏输入，只显示输出
#\| output: false (🔵) 隐藏输出
#\| output: asis (🔵) 将输出作为原始 markdown 渲染
#\| hide_line (📓) 在行末使用，隐藏该行代码
#\| filter_stream <keyword> (📓) 从输出中过滤包含指定关键词的行
#\| code-fold: true (🔵) 折叠代码（true=默认折叠，show=默认展开）

导出

指令 效果
#\| default_exp <module> 设置默认导出模块名
#\| export 导出到模块 + 文档。自动加入 __all__
#\| exporti 内部导出：导出到模块但不加入 __all__ 和文档。等价于 _ 前缀命名
#\| exports 同 export，但额外显示源码

执行

指令 效果
#\| exec_doc (📓) 每次生成文档时重新执行此 cell
#\| eval: false (🔵) 测试时跳过此 cell

开发工作流

1. 写 Notebook

每个 notebook 顶部有 markdown frontmatter：

# 页面标题

> 页面描述/副标题
#| default_exp core
  • 导出函数/类用 #| export
  • 导出但不公开用 #| exporti 或下划线前缀
  • 在导出 cell 后紧跟测试/示例 cell（用 assert 或 fastcore.test）
  • 每个 notebook 底部建议加 #| hide; import nbdev; nbdev.nbdev_export()

2. 文档化

  • docments：类型注解 + 行末注释即可自动生成参数表
def foo(x:int,            # X 轴坐标
        y:int=0           # Y 轴坐标，默认 0
        ) -> str:         # 返回的字符串
    "简短的一句话说明"
  • show_doc(sym)：在 notebook 中显示任意符号的文档（用于方法文档化）
  • doclinks：用反引号包围符号名自动生成链接，如 `myproject.core.foo`
  • 类方法文档化两种方式：show_doc(ClassName.method) 或 @patch 装饰器

3. 导出

nbdev-export          # 导出所有 notebook → .py 模块
nb-export nb.ipynb    # 导出单个 notebook

4. 测试

nbdev-test                          # 测试所有
nbdev-test --path nbs/00_core.ipynb # 测试单个
nbdev-test --flags "notest"         # 强制运行被标记跳过的 cell
nbdev-test --n_workers 0            # 单线程（调试用）

tst_flags 在 pyproject.toml 中配置，测试时跳过包含这些标记的 cell。test_nb() 返回 (success:bool, duration:float)。

5. 清理

nbdev-clean    # 剥离多余元数据，避免 git 合并冲突

6. 双向同步

nbdev-update              # .py 中的小修改 → 回传到 notebook
nbdev-update core.py      # 只更新指定模块

限制：不能新建/重排 cell，仅限已有 cell 内的修改。需要 .py 中有 # %% path/nb.ipynb #cell_id 标记。

7. 发布

nbdev-pypi          # 发布到 PyPI
nbdev-conda         # 发布到 conda

最佳实践摘要

  1. 短 docstring：一行总结即可，细节放在 prose cell + 代码示例中
  2. docments：类型注解 + 行末注释 → 自动参数表
  3. cell 短小：拆分长函数，用 @patch 分散方法定义
  4. 立即演示：代码 cell 后紧跟示例/测试 cell
  5. 测试即文档：示例 cell 加 assert，既是文档也是测试
  6. doclinks：反引号符号名自动超链接
  7. _repr_markdown_：给类添加富文本表示
  8. H2 分组：markdown ## 分组相关符号；#### 子分组详细说明
  9. show_doc 文档化方法：类定义在同一 cell 时用 show_doc(Method)；拆分 cell 时用 @patch
  10. 错误文档化：test_fail 优于 docstring 中的 “raises” 段落
  11. autoreload：notebook 顶部 %load_ext autoreload; %autoreload 2

  • 不要在同一个 cell 中混合 import 和其他代码（会导致文档生成时的副作用）

  • Windows 仅支持 WSL
  • 导出的 .py 包含 cell ID 标记：# %% path/nb.ipynb #cell_id

fastllm Concise Reference

Unified Async LLM API

Swap providers without changing code.

fastllm gives you a single acomplete function that works identically across Anthropic, OpenAI (Responses + Chat), Gemini, and OpenAI-compatible providers like DeepSeek, Kimi, Qwen, Mimo. Define messages and tools once in a canonical format, then switch models by changing one string.

Layout Rules

  1. Line width: ≤~140 chars.

  2. One line = one idea: put if + its 1-line body on one line using :; never use ; to combine multiple statements.

  3. Ternary operator: x = y if a else b.

  4. Single-line bodies preferred for short with, open, try, except, for, and if statements, plus small one-line functions that don’t need a docstring:

    • Good: if not data: return None, def _is_ready(self): return self._ready.is_set()
    • Bad: spreading short bodies across multiple lines

  5. Group similar 1-liners without blank lines between:

    def det_lighting(b, c): return lambda x: lighting(x, b, c)
def det_rotate(deg): return lambda x: rotate_cv(x, deg)
def det_zoom(zoom): return lambda x: zoom_cv(x, zoom)

  6. Align conceptually similar parts for visual diffing:

    if self.store.stretch_dir==0: x = stretch_cv(x, self.store.stretch, 0)
else:                         x = stretch_cv(x, 0, self.store.stretch)

  7. Destructuring assignment for class members (no spaces after commas, spaces around =):

    self.sz,self.denorm,self.norm,self.sz_y = sz,denorm,normalizer,sz_y

  8. Be frugal with vertical whitespace; group imports on one line:

    import PIL, os, numpy as np, math, collections, threading
    • Good: from mymod import (a, b)
    • Bad: from mymod import a,b

  9. Continuation lines indent 4 spaces beyond the opening block; don’t add extra hanging indent.

  10. Standalone ), ], } attach to the end of the previous content line — not on their own line.

  11. Indent: 4 spaces; no trailing whitespace.

  12. Operator spacing: follow domain notation — no spaces around / in pathlib, math-like spacing in equations.

Structure

  • Favor small helpers over repetitive blocks:
    • Good: def _send_stream(self, name, text): ...; self._send_stream("stdout", out)
    • Bad: self._send(sock, "stream", {"name": "stdout", "text": out}, parent)
  • Use comprehensions or inline expressions when they improve clarity:
    • Good: ids = [m["header"]["msg_id"] for m in msgs]
    • Bad: ids = []; for m in msgs: ids.append(m["header"]["msg_id"])

Typing

  • Never add type annotations to LHS assignments (e.g. x: int = 1), except dataclass fields.
  • Keep annotations simple; avoid nested generics beyond one level unless you have a strong reason.

Algorithm Guidelines

  • Implementation should be at least as fast, accurate, and concise as alternatives. Profile hotspots.
  • Must scale: work in 16GB RAM on arbitrary datasets → use generators, not lists.
  • Add equation number comments from paper being implemented.
  • Use numpy/pytorch broadcasting over loops.
  • Use advanced indexing over specialized indexing methods.
  • Test on multiple datasets and compare to existing approaches before PR.

Documentation

  • Docs go in docs_src notebooks → generate HTML.
  • Use brief single-line docstrings for multi-line functions:
    • Good: def run(self): "Run the thread." ...
    • Bad: def run(self):\n """\n Run the thread.\n """\n ...
  • In code: one-line docstring with back-quoted references to main params.
  • Style model: Python re module docs.
  • Use docments (inline # comments in signatures) for parameter docs.
  • Comments: only explain why, not how. Code should be self-explanatory. Add very few comments.

Testing

  • All tests must pass before changes are considered complete.

Other Rules

  • Assume latest Python + libs. Note if relying on something < 2 months old.
  • Link to paper/external doc in code.
  • import * is fine if using most of a module; use __all__ for internal symbols.
  • No automatic linters/formatters (autopep8, yapf, etc). Manual layout only.
  • Keep PRs small; discuss controversial changes on forums first.

When documenting functions, classes, and whatnot, use the docments spec.

fastcore.docments — SUPERDOCS

Document function/class parameters using inline comments instead of (or in addition to) docstrings.

from fastcore.docments import *

Core Concept

docments lets you document parameters with # comments directly in function signatures, instead of repeating parameter names in numpy/Google-style docstrings:

def add(
    a:int, # the 1st number to add
    b=0,   # the 2nd number to add
)->int:    # the result of adding `a` to `b`
    "The sum of two numbers."
    return a+b

Multi-line comments above a parameter are also supported:

def add(
    # The first operand
    a:int,
    # This is the second operand.
    # Passing negative is equivalent to subtraction.
    b:int,
)->int: # Result
    "Add `a` to `b`"
    return a+b

Works with: functions, async functions, classes (__init__), methods, dataclasses, @delegates, numpy-style docstrings, and mixed styles.

API Reference

docments(s, full=False, eval_str=False, returns=True, args_kwargs=False) → AttrDict

The primary function. Extracts parameter documentation from s.

Param Type Default Details
s callable/class — Function, class, or method to extract docs from
full bool False If True, values are dicts with keys anno, default, docment. If False, values are just the docment string (or None). When full=True, args_kwargs=True is always set.

Usage Notes

  • @delegates support: docments automatically follows the __delwrap__ chain, so delegated params from wrapped functions are included.
  • Dataclass caveat: If the class was defined in a notebook, docments won’t contain param comments until the notebook is converted to a module (source code unavailable at runtime).
  • Mixed styles: You can freely mix inline # comments and numpy-style docstring params. Inline comments take priority for any param documented in both places.
  • All rendering classes inherit from _DocmentBase which calls docments(obj, full=True, eval_str=True) and stores result in self.dm.

Trade-off: @dataclass vs regular class with store_attr()

在 solveit/notebook 环境中，@dataclass 的 docments 注释（# 注释）无法被 docments() 提取，因为 dataclass 在 notebook 里定义时没有源码文件可供解析。docments(MyDataclass) 会返回 None。

解决方案：用普通类 + store_attr() 代替 @dataclass，这样 docments 可以正常工作。

# ❌ Dataclass — docments 在 notebook 里不可用
@dataclass
class Video:
    id:str          # Video ID
    port:int        # SSH Port

# ✅ 普通类 + store_attr — docments 正常工作
class Video:
    def __init__(self,
        id:str,          # Video ID
        port:int,        # SSH Port
    ): store_attr()

用 @docs 装饰器可以给类的方法加 docstring（通过 _docs 字典），但它不影响字段的 docments。
